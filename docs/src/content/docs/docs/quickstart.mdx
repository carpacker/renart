This walks you from an empty repository to a materialized, scheduled
pipeline using the built-in demo project. It runs locally against DuckDB —
no warehouse or credentials needed.

## 1. Start Renart

```bash
mkdir my-pipelines && cd my-pipelines && git init
renart
```

Since the workspace has no pipelines yet, Renart opens the welcome screen
with three options: **Start from a demo**, **Import existing tables**, and
**Start empty**.

## 2. Create the demo project

Choose **Start from a demo** and pick the retail demo — a small seed-and-SQL
pipeline (bundled customer and order CSVs feeding analytics tables) that runs
entirely offline. Renart scaffolds the project files, creates a local
DuckDB connection, and runs the pipeline once so you land in a workspace
with real data in it.

Everything it created is plain files — run `git status` to see the whole
project.

## 3. Read the canvas

  src="/docs-media/pipeline-canvas.webp"

The **Build** view shows your pipeline as a canvas: each node is an asset,
each edge a dependency, and the badge on every node tells you whether it's
fresh or needs a rebuild. Click any asset to open it in the editor with its
workbench alongside.

## 4. Preview and materialize

Select an asset and use **Inspect** in the results panel to preview the
data it produces — previews have no side effects. When you change its SQL,
the asset's badge flips to **Edited** and its downstreams to **Upstream
changed**; the **Build stale** button rebuilds exactly what changed and
nothing else.

## 5. Put it on a schedule

Open **Schedules** and click **New schedule**. Pick the pipeline, an
environment, a cron expression, and a timezone — Renart deploys a snapshot
of the working tree and runs it on that cadence. Runs land in the **Runs**
view with per-asset timing and logs.
