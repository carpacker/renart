---
title: CLI reference
description: Commands and flags for the renart CLI.
---

The `renart` binary contains the whole product. `renart --help` and
`renart <command> --help` are always authoritative for your installed
version.

| Command | Purpose |
| --- | --- |
| `renart` | Start the desktop app (the default). |
| `renart web` | Start the Renart IDE. |
| `renart run` | Run a pipeline or asset. |
| `renart render` | Preview one saved asset without executing it. |
| `renart ls` | List pipelines or assets. |
| `renart type-check` | Validate a pipeline's saved assets. |
| `renart deploy` | Snapshot a pipeline for scheduled execution. |
| `renart init` | Scaffold a project. |
| `renart standalone` | Start the desktop app. |

Commands that take a pipeline or asset find your workspace the way git
finds a repository: they walk up from the current directory, so you can run
them from anywhere inside a project. Pass `--workspace` to point somewhere
else.

## renart web

Starts the Renart IDE in your browser.

```bash
renart web [options] [workspace root]
```

| Flag | Default | Meaning |
| --- | --- | --- |
| `--host` | `127.0.0.1` | Host interface to bind. |
| `--port` | `8080` | HTTP port; if taken, the next free port is used. |
| `--no-open` | | Don't open the browser after startup. |
| `--watch-mode` | `auto` | Workspace watcher: `auto`, `fsnotify`, or `poll`. |
| `--watch-poll-interval` | `2s` | Poll interval when polling. |
| `--scheduler` | | Run the local in-process scheduler. |
| `--scheduler-state` | `.renart/state.db` | Scheduler SQLite state path. |
| `--tls-cert`, `--tls-key` | | Serve HTTPS/HTTP2 with the given cert and key. |

## renart run

Runs a pipeline or a single asset and streams the output. Without an
argument it runs the pipeline enclosing the current directory.

```bash
renart run                    # the pipeline around you
renart run acme_shop          # a pipeline by name
renart run marts.daily_revenue
renart run acme_shop/assets/marts/daily_revenue.sql
```

If the Renart IDE is open on the same workspace, the run goes through it —
run history, freshness badges, and the results panel update live, exactly
as if you had pressed Build. Without one, the run executes in-process and
the IDE picks up the results the next time it starts.

| Flag | Meaning |
| --- | --- |
| `--downstream` | Asset targets only: also run everything downstream. |
| `--refresh-upstreams` | Asset targets only: first build stale transitive upstreams using their configured strategies. |
| `--full-refresh` | Rebuild from scratch instead of running incrementally. |
| `--env` | Environment to run against (default: the workspace's selected environment). |
| `--start-date`, `--end-date` | ISO dates for the run window (default: the pipeline schedule). |
| `--json` | JSON-lines events for scripting. |
| `--quiet` | Only the final status line — good for CI. |
| `--local` | Run in-process even when the IDE is open (not recommended: the two can contend for the warehouse). |

Exit codes: `0` success, `1` the run failed, `2` usage error.

## renart render

Previews the saved operations for one asset without executing them or
connecting to a warehouse.

| Flag | Meaning |
| --- | --- |
| `--workspace` | Use a workspace other than the one found from the current directory. |
| `--env` | Environment whose render context is used. |
| `--start-date`, `--end-date` | ISO dates for the preview window (default: the pipeline schedule). |
| `--execution-time` | RFC 3339 timestamp used by templates (default: now). |
| `--full-refresh` | Preview full-refresh behavior when the environment permits it. |
| `--json` | Emit the structured render response as JSON. |
| `--local` | Render in-process even when the IDE is open. |

```bash
renart render marts.daily_revenue
renart render --json acme_shop/assets/raw/customers.asset.yml
```

If the IDE has the workspace open, the command delegates to that server and
uses the same render service as the Build workbench. Otherwise it uses the
read-only service in-process without starting the scheduler or state database.

SQL stages distinguish the exact compiled query from execution SQL. Non-SQL
assets can show semantic operations, while Python is marked runtime-only
because its code decides the final operations at runtime. Every stage reports
its fidelity; a semantic or runtime-only stage is not presented as exact SQL.
Configured column and custom quality checks are listed as individually named
stages, with their exact destination-specific SQL when the direct runtime can
render it without a warehouse. Credential values are redacted or omitted.

Exit codes: `0` preview produced, `1` render error or unsupported asset, `2`
usage error.

## renart ls

Lists pipelines or assets in the workspace.

```bash
renart ls                  # pipelines: name, assets, schedule
renart ls assets           # every asset
renart ls assets acme_shop # assets of one pipeline
```

`--json` emits the same listing as JSON.

## renart type-check

Type-checks a pipeline's assets — declared dependency existence, SQL columns
and types, materialization configuration, and missing column declarations. Exit
code is non-zero on errors, which makes it a natural CI step.

```bash
renart type-check [options] [pipeline name or directory]
```

| Flag | Meaning |
| --- | --- |
| `--json` | Emit the full report as JSON. |
| `--strict` | Also fail on warnings. |
| `--start-date`, `--end-date` | ISO dates for the template date context (default: the pipeline schedule). |

## renart deploy

Snapshots a pipeline so scheduled runs execute the deployed version, no
matter what you edit afterwards. The same action as **Deploy** in the
schedules view.

```bash
renart deploy [pipeline name or directory]
```

## renart init

Scaffolds a new project — the same templates the welcome screen offers.

```bash
renart init my-project --template retail
```

| Template | Contents |
| --- | --- |
| `empty` | A minimal pipeline to build on (default). |
| `retail` | An offline seed-and-SQL demo with bundled CSV data. |
| `chess` | A live demo pulling from the public Chess.com API. |

The directory becomes its own git repository (with an initial commit)
unless it is already inside one.

## renart standalone

Runs Renart as a desktop app (an embedded server plus a native window).
Takes the same watcher and scheduler flags as `renart web`; `--port`
defaults to `0`, which picks a free loopback port. Running `renart` without a
subcommand is equivalent to `renart standalone`.
