---
title: Renart & the Bruin CLI
description: Renart projects are plain files the open-source Bruin CLI can also run.
---

Renart runs on the open-source [Bruin](https://github.com/bruin-data/bruin)
execution engine, and a Renart project is a valid Bruin project: the same
asset files, the same pipeline definitions, the same config. You don't need
to know Bruin to use Renart — but the compatibility is a deliberate
promise.

## What that buys you

- **No lock-in.** Assets are ordinary `.sql`, `.py`, and `.yml` files. If
  you stop using Renart, the project still runs.
- **Terminal interop.** Anything the `bruin` CLI can do — run a pipeline
  from a script, execute in a container — works against the same
  repository, unchanged.
- **Existing projects just open.** If you already have a Bruin project,
  `renart web` in that repository gives you the canvas, editor, staleness
  tracking, and schedules on top of it.

## When you'd reach for the CLI

Renart covers editing, previewing, materializing, scheduling, and history.
The `bruin` CLI remains useful for scripted or containerized execution in
environments where you wouldn't run a UI. Both operate on the same files,
so mixing them is safe.

For the file format itself, see the
[asset file format](/docs/reference/asset-file-format/).
