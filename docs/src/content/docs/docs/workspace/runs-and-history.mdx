The **Runs** view is the record of every pipeline execution — manual,
scheduled, or triggered over the API. "What happened last night" is a
click, not an investigation.

## What a run records

Each run stores the pipeline, the environment it ran against, what
triggered it, and a per-asset breakdown: status, start time, and duration
for every asset in the run.

## Read a run

Open a run to see its detail page:

<img
  src="/docs-media/run-detail.webp"
  alt="A failed run's detail page: a per-asset timeline showing five succeeded assets and one errored, with the event log below showing the SQL error that failed the run"
  width="2800"
  height="1800"
/>

- The **timeline** at the top shows each asset as a bar — when it started,
  how long it took, and whether it succeeded or errored.
- The summary on the right counts assets by state (preparing, executing,
  errored, succeeded).
- The **Events** log below records each asset start/finish; on a failure,
  the error — for example the exact SQL binder error — is right there in
  the log. **stdout** and **stderr** tabs hold the raw output.

## Re-run

Use **Re-execute** on a run's detail page to run the same pipeline against
the same environment again. Runs started from a schedule execute the
pipeline's deployed snapshot; manual runs execute the working tree.
